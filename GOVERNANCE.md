# Governance

HayaSend is maintained by Haya, Inc. in public.

- Maintainers make technical decisions based on security, compatibility,
  operational safety, and long-term maintainability.
- Material API changes require an issue or proposal and a documented
  compatibility decision.
- Maintainers may reject features that weaken deliverability, privacy,
  anti-abuse controls, or the ability to operate the project safely.
- The issue tracker and
  [roadmap](https://github.com/haya-inc/hayasend/issues?q=state%3Aopen%20label%3Aroadmap)
  are public. Commercial customers may fund work, but accepted changes must
  remain coherent with the public project.
- The Apache-2.0 license applies equally to community and commercially funded
  contributions.

## Roadmap decisions

- Release milestones define evidence-based gates, not calendar promises.
- A `roadmap` label means the problem and constraints are accepted; it does not
  guarantee priority, implementation, or a delivery date.
- Material proposals remain open for public technical review before runtime
  implementation.
- Security vulnerabilities use private advisories and are disclosed publicly
  only after coordinated remediation.
- Commercial funding may change sequencing but does not create a private fork
  of security fixes or accepted core product behavior.

Maintainer and release processes will be expanded before v1.
